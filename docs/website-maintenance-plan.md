# AGI 官网后续维护计划

状态：第 0 阶段已发布并通过公网核验；第 1–3 阶段仍是计划，不表示相应功能已实现。
核对日期：2026-10-26（引用的 MHTML 快照下载于 2026-10-25）

## 已确认的维护目标

官网要服务两类不同场景：读者浏览静态知识资料，以及教师在不使用 Agent、Obsidian 或 GitHub 的情况下维护内容。现有站点以 VitePress 构建静态页面；本地管理员编辑演示仅覆盖本机草稿、差异、预览、审核和版本恢复，不具备真实账号、权限或线上发布能力，也不在网站部署产物中。

维护者还提出“新闻动态”自动抓取、整理和呈现，并指出未来可能需要静态内容与动态内容并存。当前新闻入口不等于已建立采集、后台或自动发布链路。新增能力需先形成可审阅流程，再考虑动态服务。

### 1. 面向教师的页面内编辑与在线编辑验收

目标用户是能使用浏览器和常见办公软件、但不使用 Agent、Obsidian 或 GitHub 的教师。验收重点是教师能独立把一条已批准的内容从草稿带到可核验的正式页面。

先确定可编辑范围：常规文章标题与段落、链接、人物简介中受控字段和图片替换；页面布局、导航、脚本、主题组件等工程内容仍由维护者管理。遇到编辑器不认识的 Markdown、Vue 组件或媒体结构时必须保留原文并提示，不能静默改写或丢弃。

拟议流程为：身份验证与最小角色权限 → 打开页面 → 编辑草稿 → 自动保存与离线/断网恢复 → 差异预览 → 内容与图片来源检查 → 提交审核 → 有权审核者批准 → 明确发布 → 版本记录与回退。草稿、已批准、已发布分别显示状态；保存或审核成功都不代表已上线。

在实现真实认证、远端写入或发布前，需单独审查权限方案、密钥保管、冲突处理、审核责任和回退策略。当前本机 demo 的模拟角色和本地 Git 历史不能作为线上权限验证。

**教师人工验收清单**

- [ ] 教师能在无需终端、Obsidian、GitHub 或 Agent 的情况下，找到并编辑获准的页面。
- [ ] 使用 Windows 中文输入法输入、组合态确认、方向键移动、粘贴和撤销/重做均正确；需用真人 IME 与实体键测试。
- [ ] 草稿自动保存、重新打开恢复、断网提示、保存重试与并发编辑冲突有明确结果。
- [ ] 差异预览易读；链接、图片替代文字、来源与版权信息可检查；未知格式不丢失。
- [ ] 审核人、批准时间、当前发布版本及历史回退路径清楚可见。
- [ ] 未授权者不能发布；取消、权限不足、发布失败不会误显示为成功。
- [ ] 390px 窄屏、桌面、125%/150% 缩放、键盘焦点和屏幕阅读器另行实测。

### 2. 新闻动态的采集、整理与呈现

先由维护者确认来源白名单、内容范围与更新节奏。优先使用来源方公开 RSS、API 或可再分发数据；站点不提供明确渠道时，先核对其使用条款与 robots 规则，不绕过登录、验证码、访问控制或限流。

第一阶段建议把采集结果生成为带来源和时间戳的静态 JSON，经过去重、分类、失效链接检查和人工审阅后再随站点构建发布。每条至少保留原始标题、来源名称、原文链接、发布时间（含时区或日期精度）、采集时间、摘要来源/编辑者和审核状态。自动发现不等于事实确认或自动发布；转载内容应控制摘录长度并优先链接原文。

推荐先验证一条可回滚的闭环：来源配置 → 定时或手动采集 → 暂存候选 → 去重与分类 → 人工审核 → 生成站点数据 → 构建检查 → 发布 → 记录失效与回退。保留失败记录与上次成功时间，避免抓取故障时把空结果覆盖成“没有新闻”。

GitHub Pages 可呈现预生成的数据，但不运行常驻服务或安全保存私密 API 密钥。如果后续需要登录态、实时查询、用户提交或更细权限，再比较独立后端/API 与静态快照方案；先画出数据流、成本、密钥边界和故障回退，再由维护者决定架构。

### 3. 静态与动态架构决策

保持 Markdown / Git 为当前权威内容源。允许前端通过静态 JSON 呈现更新频率较高的新闻索引；如需动态 API，应与静态 Wiki 的部署、认证和失败回退分开设计。决策材料至少比较：更新时效、维护负担、凭据安全、来源许可、搜索与归档、离线可用、失败降级和迁移成本。

在新闻采集试点和教师编辑验收前，不新增线上数据库、公开写入接口、自动发布凭据或持续爬虫，不改变生产 DNS、腾讯云服务器配置、WordPress 替换范围或访问权限。
