# 官网全替换：WordPress 功能对等与迁移路线图

核验日期：2026-10-19。范围：公开官网导航与页面、公开文章接口，以及 Wiki 先锋版代码基线 f79d9c4。本文是功能台账和验收计划，不是功能已完成声明。当前工作只制作独立预览，不登录后台、不修改正式站、不切换域名、不建立认证、不安装软件。

## 1. 目标与证据边界

最终目标是承接现 WordPress 官网全部实际使用的功能、编辑运营和必要历史数据，而不只是重新设计前台。功能覆盖与内容融合分开验收：只将 WordPress 独有、并经过实际信息核对证实有效的内容融入当前正文；重复或过时内容不直接迁入当前正文。历史内容与来源保留在迁移清单或归档中，不因此删除数据。先锋版目前是 VitePress 内容站；不能把静态预览包装成已具备 CMS 后台的正式替代品。最终技术选型应在后台盘点后确定，不预设必须继续使用或必须弃用 WordPress。

证据等级：
- **F：已证实前台**。可从公开页面或当前源码观察。
- **D：已证实后台依赖**。公开输出能确认依赖存在，但不能证明后台配置、操作流程或权限细节。
- **C：候选能力，未确认**。WordPress 或类似站点常见能力，不代表本站已启用。
- **A：需要管理员材料**。前台无法完整核实的本站事实。

已确认的生产依赖是 WordPress、Astra 主题、Elementor 页面输出、WP 媒体路径与公开文章数据。HTML 也出现 SureRank SEO 标记；只证明有该标记，不能推定当前插件配置、许可或全部 SEO 功能。未盘点后台插件清单，不将报名、支付、会员、邮件订阅、多语言或任何其他默认/常见能力列为本站已启用。

## 3. 最少管理员材料

无需提供密码、密钥、令牌或扩大任何权限。可由管理员自行导出或通过只读演示提供：

1. 已启用和停用插件清单、主题/子主题清单及版本；必要时隐藏许可证和密钥。标出哪些插件承担关键业务。
2. 角色和实际人员职责说明，或去身份化的角色-能力矩阵；用一条真实流程演示创建、审核、发布、修改、撤回。无需提供用户密码或密码哈希。
3. WordPress内容导出（WXR/XML，按管理员许可范围），媒体文件清单/归档与公开URL；统计文章、页面、草稿、附件、评论和自定义类型数量。含非公开或个人数据的导出应通过获准的安全通道提供，避免提交公开仓库。
4. 评论配置和去敏化样例，包含线程、审核状态、日期及匿名显示规则；无需收集评论者邮箱/IP等与公开迁移无关的数据。
5. 实际表单、报名、邮件、订阅、外部集成清单，以及字段/收件目标/通知/失败处理的只读演示。没有这些材料，相关功能保持“待确认”。
6. 当前URL/重定向、SEO、站点地图、RSS、缓存/CDN配置的去敏化说明；现有备份、恢复步骤及部署回滚方式。凭据和运维秘密不得进入路线图或代码仓库。

这些材料用于完成差异清单，不等于授权登录、部署、认证或更改正式环境。

## 4. 数据迁移方案

- 建立“源ID → 类型 → 源URL → 目标路径 → 迁移状态 → 校验结果”清单；覆盖页面、文章、附件、人物、评论和自定义类型。
- 每条正文候选标注“WordPress独有且有效/重复/过时/尚待核验”。只有第一类融合入当前正文；其余按需保留可追溯归档或待核验记录，不重复堆入页面。招生信息亦遵循此准则，不因它是独有入口而自动整篇复制。
- 保存原始导出只读副本与校验和。公开内容可进入内容仓库；私密草稿、个人资料和运维数据隔离保存，遵守最小访问权限。
- 保留发布日期/修改日期、作者展示、分类标签、正文结构、图片说明、附件关联和可核实的许可。不要把迁移时间当原始发表时间。
- 评论迁移单独处理源ID、父ID、文章关联、状态和时间；明确公开字段。联系页隐藏评论不改变保存清单。若新系统不支持原线程，至少提供经同意的只读归档和管理查询，不伪造用户名或审核状态。
- 下载/转存文件前确认授权和许可；批量比对字节数/校验和、路径和引用。保持旧资源可访问，或提供一对一重定向；不得只保留缩略图丢失原件。
- 正式切换前确定内容冻结或增量同步窗口，防止迁移期间新文章/评论丢失；保留最后一次增量记录。

## 5. 旧URL与内容纠错

必须纳入映射：
- `/` → 新官网首页。
- `?page_id=642` → `/about/`；`?page_id=16` → `/research/`；`?page_id=18` → `/conference/`。
- `?page_id=710` → `/conference/annual/`；`?page_id=708` → `/conference/group/`；`?page_id=20` → `/learn/`。
- `?p=789` → 经确认的招生页路径。
- `/conferences/`、`/papers-and-projects/`、旧 `/wiki/...`、wiki子域路径、附件URL、HTTP/HTTPS及www/裸域变体。

以上为首批清单，不是全量URL导出。查询参数重定向须由网关/服务器或等效路由层处理，不能仅靠静态页面文件。避免链式跳转和将所有未知路径重定向首页；保留有帮助的404。

已发现错误：旧710和708将2025写成四川成都，708内容为年会列表；实时18写辽宁锦州。Wiki细页写辽宁工业大学和渤海大学并有录像。保留来源记录，由内容负责人采用可靠材料核对。官网首页“连续10届”与第11届宣传不一致；2026会议日期已过，不展示正在报名。不能用这次迁移自行决定有争议的学术事实。

## 6. 分阶段交付与验收

### 阶段一：公开预览
- 页面、导航、学习路径、人员、会议和真实链接可用；新增内容有来源。
- 联系页不显示评论；其他评论策略不被一刀切删除。
- 预览明确独立环境，不调用正式提交/付款/评论写入，不暴露秘密。
- 本阶段完成不代表CMS、后台权限、数据迁移或全站替换完成。

### 阶段二：后台发现与技术决策
- 管理员确认功能台账，无关键功能仍靠猜测。
- 对每项实际能力标注“直接承接/替代实现/经同意退役/待决定”，给出负责人和验收证据。
- 决定内容编辑后台、评论系统、媒体管理、认证和部署架构。任何新持久授权、安装或正式配置变化另行获得所需批准。

### 阶段三：隔离迁移演练
- 源/目标各类型数量对账；每项缺失有说明，抽样包括复杂页面、中文路径、长正文、附件和嵌套评论。
- 实际编辑者验证草稿、审核、定时发布（若启用）、预览、修订、发布和撤回。负面测试验证无权者不能发布、改权限或看私密草稿。
- 评论审核、垃圾过滤和归档按实际需求验证；禁止向真实用户发送演练通知。
- 搜索测试中文标题、正文关键词、人员和年份；移动端、键盘导航及基本可访问性检查。
- 对所有已知旧URL测试响应状态、目标、canonical与锚点；SEO、RSS、robots、站点地图和分享卡片逐项检查。

### 阶段四：恢复与回滚演练
- 从备份在隔离环境恢复内容、数据库/评论（如适用）、媒体、配置和部署产物；仅有“备份成功”日志不算通过。
- 明确恢复点目标与恢复耗时目标，由运营负责人确认；不得自行杜撰数值。
- 记录发布版本、配置版本、内容快照和回滚入口；演练旧版本恢复及新增数据保全。
- 回滚触发条件至少包括关键页面/提交不可用、数据缺失、权限泄露、旧URL大面积失败和不能安全恢复。定量阈值在上线前批准。

### 阶段五：获准正式切换
- 仅在迁移/权限/SEO/恢复验收签字和明确部署授权后操作正式域名。
- 在约定窗口冻结或同步源内容，执行最后增量和校验，保留原站及备份可恢复。
- 上线验证真实读取、必要的获准提交、评论审核和通知路径；监测错误、索引与关键任务。
- 出现回滚条件时按获准方案执行，先保全切换后新增数据；禁止覆盖或丢弃真实提交。
- 稳定观察期和旧系统退役时间由运营负责人批准。旧WP下线、删除数据或撤销备份是独立决定，不包含在“新版上线”默认动作中。
