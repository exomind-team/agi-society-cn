# 管理员文字编辑工作台 0.1

## 本轮范围

- 依照用户 2026-10-21 的方向：普通编辑者不接触 Git；先管理员、先文字，后续再做样式与公开投稿。
- 独立原型，不改当前官网、先锋分支或部署配置。
- `web/index.html` 对接同源真实 API；连接失败保留失败状态，不自动切换成假成功演示。
- `admin-editor-demo.html` 为可单文件打开的交互演示。醒目标注仅当前页面内存，刷新重置；不连接服务器、不修改官网。

## 设计决策

采用安静的蓝灰内容工作台，左侧页面列表，正文作为主要工作区域。没有营销首屏和大块仪表卡。保存草稿与确认正式版本始终可见；格式说明、历史和外部同步按需展开。红绿变化同时包含 +/−、新增/删除标签，不依赖颜色。

主动作使用「确认正式版本」而不是假称「发布到网站」。本轮后端只创建本机内容仓库正式版本，尚未连接构建、部署或公开托管同步。每次结果按这一实际层级反馈。

编辑器是正文纯文本输入，不声称所见即所得。阅读预览只用 `textContent`，不会执行 HTML、Vue 组件、脚本、外部图片或链接。来源按现有正文格式保留，没有凭空添加不兼容的元数据字段。

变化比较裁掉相同首尾，中间按完整删除/新增块展示；这是明确标注的简洁块级比较，不伪称最小逐行 diff。长文精确行级算法为后续优化。

## API 契约

与后端代理约定：GET `/api/pages`；POST `/api/action` JSON 包含 action 和参数。见后端 `API.md`（后端完成后）。

- read、saveDraft、publish、history、readVersion、restore、syncStatus。
- `baseRevision` 与 `expectedDraftRevision` 用于草稿冲突；正式版本操作必须带 `expectedRevision`。
- 请求失败保留输入；409 呈现可下载当前文字、载入最新版的恢复路径。不会静默重试覆盖。
- 预览当前未保存文字是本地阅读，不发送写请求。
- 恢复创建新正式版本、不删除历史；明确提示原草稿可能陈旧，需要比较。
- 双击重复操作由 busy 守卫；迟到页面读取有 generation 隔离。

## 输入、键盘与可访问性

全部操作为原生按钮、输入、textarea、details、dialog；标签、可见焦点、跳至正文、状态播报、模态取消入口齐备。Ctrl/⌘+S 仅有当前页面且非 IME、非弹层时保存草稿。没有额外动效阻碍输入。窄屏页面选择改为水平列表，主保存动作保留。

未保存时切换页面明确确认；关闭窗口由 beforeunload 请求浏览器提示，浏览器是否展示依宿主策略。下载纯文字作为冲突恢复出口。

```
node scripts/build-demo.mjs
node --check web/app.js
node --test tests/ui.test.cjs tests/ui-host.test.cjs tests/ui-backend-integration.test.mjs
```

2026-10-21：22 项测试通过（16 项 Node 逻辑/静态、5 项受控 DOM 事件、1 项实际 Git 存储集成），覆盖草稿/正式分离、显式写入、未保存拒绝、双编辑冲突、恢复新版本、HTTP 错误和 JSON 契约、迟到请求、保存期间输入与安全 DOM 写入的结构检查。

这些不是浏览器实测。受控 DOM 只验证事件和状态代码，不验证原生焦点、排版或中文输入法；Git 集成实际建立专用临时仓库。当前原生浏览器在既有环境中被 socket 权限阻止，未绕过；未验证真实布局、焦点循环、读屏、中文输入法、下载和 mobile touch。单文件 demo 仍需真人/真实浏览器验收。

## 下一轮验收建议

1. 修改一个页面，保存后检查正式内容尚未变化。
2. 查看红绿增删、纯文字预览，再确认正式版本。
3. 两个编辑会话相互制造冲突，确认本地文字未丢失。
4. 查看历史并恢复，确认生成新版本、历史仍在。
5. 检查每次提示都没有把本机写入冒充线上更新。

追加验收：写入成功但刷新失败时保留成功版本凭据，阻止盲目重复提交；网络结果不确定时先读取核对。保留的草稿与正式内容相同时不误报未发布，陈旧草稿重新保存前明确提示比较。
